# Avalonia 迁移路线

制定日期：2026-11-20。本文是迁移计划，不表示相关能力已经实现或验收。当前架构见 [ARCHITECTURE.md](ARCHITECTURE.md)，构建和验证入口见[构建与测试](构建与测试.md)。

## 执行原则与分支约定

迁移拆成 **10 个阶段，每阶段单独提交，验收通过后再让 AI 做下一阶段**。前 6 阶段持续保持 WPF 可运行，第 7 阶段才引入 Avalonia。

- 在 `migration/avalonia` 分支实施迁移，`main` 保持当前稳定版本，用于发布和必要修复。
- 定期将 `main` 的修复合入迁移分支，减少最终合并冲突。
- 每个阶段完成后都应可构建、可验证、可独立审查；较大阶段可以拆成多个提交，但不能混入后续阶段。
- 引入 Avalonia 后保留两个启动入口，以同样的数据和操作核对行为；避免同时运行时争抢全局快捷键和单实例通道。
- 完成全量验收后再合并到 `main`。不要仅以编译成功作为验收通过。
- 本轮首先面向 Windows，保留现有截图、录屏和 AI 后端。其他操作系统的后端实现另行规划。

## 每次交给 AI 的共同约束

复制本段，再附上本次阶段的任务说明：

> 基于现有仓库完成本阶段工作。先阅读适用的 AGENTS.md 和迁移记录，确认当前依赖，再实施修改。保持现有功能、配置格式、数据目录和快捷键行为兼容。不要顺带升级依赖、重新设计界面或推进后续阶段。共享层禁止引用 WPF、WinForms 和 Avalonia；Windows 专用能力可以保留 Windows 依赖。执行与改动相关的构建和验证，记录结果及尚未验证的行为。更新 docs/avalonia-migration.md，记录已完成项、依赖边界、验证方法和下一阶段入口。结束时说明改动、验证结果与剩余问题。每阶段单独提交，仅包含本阶段修改；验收通过后再推进下一阶段。

## 第 1 阶段：建立基线和迁移清单

交给 AI 的任务：

> 盘点主程序、Libraries 和测试工具的依赖关系，识别 WPF 类型在公共接口、模型、算法及服务中的使用位置。重点检查 BitmapSource、Point/Rect/Color、DrawingContext、Dispatcher、Application.Current 和窗口句柄依赖。完善 docs/avalonia-migration.md，列出目标项目职责、分阶段迁移清单及现有验证入口。执行当前可运行的构建和相关检查，记录基线问题。本阶段只做盘点、文档和必要的验证，不修改功能实现。

验收标准：

- 明确哪些代码可以直接抽离，哪些需要类型替换，哪些属于平台或界面。
- 记录实际运行的构建、检查命令和结果，区分现有失败与后续改动造成的失败。
- 给出共享类库、平台实现、应用编排和 UI 壳的目标依赖方向。

## 第 2 阶段：抽离配置、历史和识别结果中的纯逻辑

交给 AI 的任务：

> 将配置模型、OCR/表格/公式识别结果、历史记录元数据，以及不依赖界面的序列化和规则逻辑放入合适的共享类库。历史缩略图生成、剪贴板和 UI 调度暂时留在原实现。保持 JSON 字段、默认值、历史索引和数据路径兼容，让 WPF 调用抽离后的实现。当前 Core 仍有 WPF 依赖，本阶段不要为了让整个 Core 去 WPF 而扩大范围。

验收标准：

- 旧配置和历史数据能够读取，保存后保持兼容。
- 抽离的纯逻辑不引入 UI 类型，WPF 对应流程继续可用。

## 第 3 阶段：统一图像和坐标契约

交给 AI 的任务：

> 设计并实现不依赖 UI 的图像、几何和颜色契约。覆盖像素尺寸、stride、像素格式、预乘透明度、DPI 元数据、缓冲区所有权和释放规则。区分桌面物理像素、图像像素和界面逻辑坐标。新增集中管理的 WPF 图像适配器，逐步替换 CapturedScreen、CaptureResult 及必要公共接口中的 BitmapSource。WPF 显示行为保持一致，避免业务层散落图像转换和使用 PNG 编解码作为默认桥接方式。

验收标准：

- 图像转换后尺寸、颜色和透明度正确。
- 转换成本、线程使用规则和资源释放责任清晰。
- 坐标转换保持现有裁剪精度，覆盖负坐标和混合 DPI 场景。

本阶段是后续图像处理、编辑器和平台接口迁移的关键前置条件。

## 第 4 阶段：抽离图像处理和拼接算法

交给 AI 的任务：

> 将 SkiaImageService 中的裁剪、旋转、缩放、编码、效果处理，以及 ScrollingStitcher 的算法部分改为使用共享图像契约。Imaging 可以依赖 SkiaSharp，但不依赖 UI 框架。实际桌面采集、滚动输入、窗口控制与算法分离。让 WPF 通过适配器继续使用这些能力，并在适当位置复用现有像素及拼接检查。

验收标准：

- 图像处理、编码和拼接算法能够脱离 WPF 窗口运行。
- 输出通过相关像素及拼接回归验证，WPF 处理和输出流程继续可用。

## 第 5 阶段：拆开标注数据、编辑状态和渲染

交给 AI 的任务：

> 拆分 Annotation.cs 中的标注数据、几何编辑逻辑和绘制实现。共享标注模型不包含 DrawingContext 或控件；Skia 绘制放入独立渲染器，WPF 预览绘制保留为界面适配实现。EditorViewModel 使用共享图像、颜色与几何类型，保留撤销重做、选择、移动、缩放、旋转及图像替换行为。保持现有标注模板格式兼容，并核对预览与导出结果。

验收标准：

- 共享编辑状态与模型脱离 WPF，现有 WPF 编辑器仍然可用。
- 标注模板、撤销重做和最终导出通过相关验证。
- 明确共享数据、编辑逻辑、Skia 导出和 WPF 交互预览各自的边界。

## 第 6 阶段：建立平台接口与应用编排边界

交给 AI 的任务：

> 根据现有调用建立最小必要的平台接口，覆盖截图、全局快捷键、剪贴板、录屏和原生窗口能力，由 Platform.Windows 提供实现。接口参数使用共享类型，不暴露 WPF Window、BitmapSource 或 Dispatcher。托盘菜单展示和遮罩交互通过展示层接口实现；窗口穿透、捕获排除等放入 Windows 原生能力服务。将 CaptureCoordinator、AppController 中的业务流程与窗口创建、UI 调度分开，从程序入口注入实现，避免静态全局服务定位器。保留现有录屏引擎。

> 清理已完成抽离的共享项目中不再需要的 UseWPF、全局 using 和继承的构建属性，使这些项目可以独立构建。检查插件契约、识别后端和测试工具，避免共享层通过传递引用继续依赖 UI 框架。若平台能力仍有具体 UI 依赖，应完成适配拆分后再结束本阶段。

验收标准：

- WPF 通过明确接口完成主要流程，平台实现不反向引用 WPF 壳。
- 已完成抽离的共享项目能够独立构建，依赖链中没有 UI 框架。
- 原生窗口能力与遮罩绘制、输入交互分离。
- WPF 的截图、编辑、输出、识别及录屏相关流程保持可用。

## 第 7 阶段：引入 Avalonia 壳，同时验证高风险原型

交给 AI 的任务：

> 新建独立 Avalonia 启动项目，与 WPF 启动项目并存，复用共享类库和 Windows 平台实现。完成启动、退出、托盘和最小设置页，接入配置、主题与本地化资源。检查根项目默认文件包含规则及 Directory.Build.props，避免新项目源码被 WPF 项目重复编译。同时实现最小截图遮罩原型，验证混合 DPI、负坐标显示器、跨屏选区、键盘取消和裁剪像素精度。本阶段只验证最小闭环。

验收标准：

- 两个入口都能独立构建运行。
- Avalonia 能完成“触发截图 → 框选 → 保存”。
- 记录真实多屏验证结果；合成坐标检查不能替代真实设备验收。
- 未验证的硬件、焦点或窗口行为明确记录，不记为通过。

## 第 8 阶段：迁移普通窗口和标注编辑器

交给 AI 的任务：

> 将设置、历史、模型管理和必要对话框迁移到 Avalonia，随后实现 Avalonia 标注编辑器。复用共享编辑状态、标注模型和导出渲染器，只在界面层实现指针输入、焦点、中文输入、缩放和平移。逐项核对现有功能清单，验证撤销重做、文字编辑、标注变换、复制保存及预览与导出一致性。不要重新实现已有业务算法。

验收标准：

- 普通窗口功能可用，标注编辑器核心工作流完整。
- 旧配置、历史及模板能够在新界面继续使用。
- 大图与连续交互的性能有实际验证结果。
- 中文输入、焦点切换和预览与导出的一致性通过验证。

本阶段较大，可以拆成“普通窗口”和“编辑器”两次任务，分别提交和验收。

## 第 9 阶段：迁移完整截图遮罩和贴图

交给 AI 的任务：

> 基于已验证的 Avalonia 遮罩原型，迁移完整选区、工具栏、放大镜、取色、窗口吸附及相关交互，再迁移贴图。保留物理像素坐标规则，接入 Windows 窗口穿透、置顶、焦点和捕获排除能力。按现有功能清单补齐，复用可共享的坐标及像素检查，为 Avalonia 实际窗口行为建立必要验证。确保 WPF 和 Avalonia 并存时不会争抢全局快捷键或单实例通道。

验收标准：

- 截图与贴图日常流程完整。
- 混合 DPI、跨屏、透明图片、鼠标穿透和窗口层级经过验证。
- 裁剪像素、放大镜和取色结果保持精确。
- 快捷键及单实例行为明确且经过验证。

## 第 10 阶段：迁移剩余窗口并完成默认入口切换

交给 AI 的任务：

> 迁移识别、图像工具、长截图和录屏相关窗口，复用现有引擎、任务状态、取消及输出流程。验证异步结果回到 UI、窗口关闭后的任务处理和资源释放。完成 Avalonia 发布、资源及原生依赖复制检查，建立与旧版的功能验收对照。验收完成后将 Avalonia 设为默认入口，保留可恢复的 WPF 版本；最后单独清理无调用的 WPF 实现和依赖。

验收标准：

- 完整功能清单、构建、相关回归检查和发布包验证通过。
- 配置兼容、截图精度、标注导出、剪贴板透明度、多屏、识别与录屏均有验收记录。
- 异步取消、过期结果处理、窗口关闭及资源释放行为通过验证。
- 默认入口切换、WPF 清理和最终合并分开审查；未验证项不能仅因编译通过而标为完成。
